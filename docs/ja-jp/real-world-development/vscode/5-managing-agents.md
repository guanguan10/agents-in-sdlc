Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat は、ローカル コンピューター上でリアルタイムに行われる作業を表示し、各ツール呼び出しとファイル編集を確認できるようにします。差分をチャット内でレビューし、変更ごとに受け入れたり拒否したりできます。また、エディターを離れずに追加のプロンプトを送って、作業を調整、拡張できます。

このレッスンでは、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして受け入れます。
- 作業中のエージェントに指示し、ハイ コントラスト モードと並んでライト モードの切り替えを追加します。

## シナリオ

[レッスン 4][previous-lesson]で使用したアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加したいという要望がありました。新しい会話を始める代わりに、現在のセッションに指示を加えて作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順、調べているファイル、実行するコマンド、提案する編集が表示されます。ファイル編集は、差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. レッスン 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択して変更を受け入れます。
   - **Undo** を選択して変更を取り消し、エージェントにもう一度変更させます。
4. チャット上部の **Files changed** 表示を開き、セッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの許可が必要な場合は、エージェントが一時停止し、**Allow** を求めます。問題ないコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、行った変更を要約するメッセージが表示されます。

## エージェントに指示してライト モードを追加する

ハイ コントラスト モードができたので、同じ会話を続けてライト モードの切り替えを追加します。同じチャット セッションを使うため、エージェントは前の作業、変更したコンポーネント、スタイル設定、設定をローカル ストレージに保存する方法を把握しています。

1. Copilot Chat の入力欄に次のプロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を確認し、ライト モードを追加します。
3. ハイ コントラストのときと同じように、新しい編集を確認し、それぞれ **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合 (たとえば、好みと異なる方法で切り替え UI をリファクタリングする場合) は、チャット入力欄の横の **Stop** ボタンで停止し、追加の指示を送ります。

> [!TIP]
> 作業中のセッションに指示を追加すると、最初からやり直すよりも速く修正できます。追加のプロンプトで調整を依頼したり (「CSS を簡素化し、セレクターの重複ではなく CSS 変数を使ってください」)、方向を修正したり (「切り替えを 3 つにせず、既存の設定パネルにライト モードを追加してください」)、範囲を拡張したり (「両方の切り替えにキーボード ショートカットも追加してください」) できます。

## 作業中の変更を確認する

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージへの保存など、カスタム エージェントのアクセシビリティ パターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使い、作業中のセッションを監視して指示を追加しました。各ファイルの編集を確認して受け入れるか取り消し、コンテキストを失わずに追加のプロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する方法。
- ファイル編集を個別に受け入れ、取り消す方法。
- 追加のプロンプトを使って作業中のセッションを方向付ける方法。

次のレッスンでは、アクセシビリティの変更をプルリクエストとして公開し、ラボでローカル カスタム エージェントが行った変更をレビューします。
